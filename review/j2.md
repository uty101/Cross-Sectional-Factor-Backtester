## Not verified

- **The Pages deployment.** Pages must be enabled once by the owner (Settings > Pages, source "GitHub Actions"); until then the workflow has nowhere to deploy and "the Pages workflow is green" in the plan's done-when cannot be checked from this machine.
- **The page in a browser.** `docs/index.html` was not opened; the tests check the HTML text and the JSON, not the rendered DOM. The done-when's "opens from disk with the current numbers" rests on the template's own JavaScript, which is unchanged apart from one sentence.
- **The `cost_bp_base` round trip** ("changing `cost_bp_base` ... changes the page with no manual edit"): not run; it is a six-minute `run-all` plus report plus site. Every cost number on the page comes from `results.csv`, which `report` writes from the runs, so the chain has no hand step.

## Open

- **The history footer's dates repeat.** Seven points at "09-11, 09-11, 09-14, 09-14, 09-15, 09-16, 09-16": one per distinct `git_commit`, labelled by date only, so two commits on one day read as the same point twice. The commit hash is the honest label; the footer has no room for it.
- **The 2026 bar is 0.0 for August 2026**, the window's last month, where every member has a close and no forward return is possible. It is what the check file says; a reader might expect the last month with a return (July, 0.2).
- **`CLAUDE.md` still says "176 tests".** Not updated in this commit.
- **`pages.yml` triggers on `paths: [docs/**]`**, so a push that changes code but not `docs/` does not redeploy, which is right, since the page is built where the data is.

## Against the plan

- **`wdnw` is not `reports/what_did_not_work.md`'s first five bullets.** That file is the uninterpreted log (one spec row per line); the example's bullets are claims, and the README's section is where those live. Recorded in `_bullets`'s docstring.
- **`history` is quality, not value.** The plan text names the quality base key; the example carried value's numbers. Plan text wins.
- **`exclusions` is a key the example lacks**; the template renders it; it is emitted and `test_every_schema_key_is_produced` asserts it separately.
- **The Dagster asset depends on `results`**, the asset that writes the figures and `validation.csv`, rather than naming those two.
- **The template changed by one sentence** (the plan says the template ships with it); the sentence said the composites are not listed while the plan says to list every row.
