## Not verified

- **That 280 is every wrong member-month.** It is every member-month the two checks can see. A reused symbol with no float (no cover count in the API file) and a plausible name passes both; H2's "Open" lists the 261 removed names with no level.
- **The text factor's move** (−0.17 → −0.09 net, coverage 98% → 96%) was not decomposed; the factor is an appendix and none of its variants leaves ±0.35.
- **The cap-weighted value move** is attributed to HAR by the arithmetic of its weight and B/P, not by a rerun with HAR alone excluded.
- **`methodology.pdf`** was regenerated and not read.

## Open

- **The by-block table is by formation month**, the convention the previous README used for the RMW rows; `decisions/g5_rmw_trough.md` blocks by month earned. The two differ by one month at each block edge; neither was changed to the other.
- **The drift agent** (`agents/drift.py`) would have read the first pass's `decisions/drift/2026-09-16.md`; it was not run (no key), the cause was found by diffing the two exclusion lists by hand, and the second pass overwrote the report. The first report's table list is reproduced in the finding above.

## Against the plan

- **`exclusions_applied.csv` carries the tickers** as well as the count per month.
- **The exclusions are applied to the member panel**, not to the signal frames one by one: a name absent from the cross-section is absent from every signal, from the returns panel, from the sector z-scores and from `min_names`, which is what "dropped before signals are computed" needs to mean for the z-scores to be right.
- **A recompute fix in this step.** The plan lists "run `recompute.full`" as a check; it found a determinism defect in H2's code (the filer index), fixed here, one line. The incremental outputs did not change.
- **`decisions/h3_before_after.md` is generated**, not typed: a script over the two `results.md` files, so every one of the 271 cells is there whether or not it moved.
