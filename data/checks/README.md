# data/checks

Committed evidence for the universe. Everything here is regenerated by
`uv run backtester build --step universe` except the hand-written files,
`membership_overrides.csv`, `membership_spotcheck.csv`, `cik_overrides.csv`,
`shares_overrides.csv` and `public_float_overrides.csv`.

| File | What it is |
|---|---|
| `membership_summary.csv` | Headline numbers: intervals, unique names in window, names per month (min/median/max), where each start came from, cross-check agreement |
| `membership_monthly_counts.csv` | Names in the cross-section at every month-end 2010-01 to 2026-08 |
| `membership_inconsistencies.csv` | Changes-table rows the walk could not place: an addition with no matching member, or a removal of a name still active. Each is a ticker rename, a share-class event, or a missing row. Nothing here is guessed at |
| `ticker_renames.csv` | Additions matched to a current member by `date_added` within 7 days (FB→META). Input to the price layer |
| `membership_adjudications.csv` | The 11 current members whose Wikipedia `date_added` falls in-window with no changes row, and what the cross-check said about each. Six were long-standing members given a corporate-event date and were pushed back; five were real additions the changes table is missing |
| `membership_overrides.csv` | **Hand-written.** Four intervals the two tables cannot express: Google's class A before the 2014 class C distribution, and three names added under an old ticker and removed under a new one (UAA, CPRI, JOY). Each row carries its evidence. Overrides only add or correct a start; they never delete |
| `membership_crosscheck_by_year.csv` | Month-end agreement with the fja05680 daily list, per year, after label differences are removed |
| `membership_crosscheck_aliases.csv` | Pairs of tickers that are the same security under the ticker of the day (cross-check) and the current ticker (this pipeline), found by identical month spans |
| `membership_crosscheck_residual.csv` | What still differs after aliases. Mostly rename chains the pairing could not disambiguate (J/JEC alongside BBT/TFC on the same span) and one-month effective-date conventions |
| `price_fetch_missing.csv` | Tickers yfinance returned nothing for, after two retries: the delisted names; and the stubs a refetch confirmed (`prices.refetch`, FIX_PLAN_4 J1: AVB 27 rows, EA 1 row, stored under `data/raw/prices/yfinance_stubs/` so the build does not read them) |
| `price_cleaning.csv` | Per ticker: dropped for having no history inside membership (first print after removal: a reused symbol or a delisting stub), bad prints removed, or dropped as corrupt |
| `price_coverage_monthly.csv` / `_summary.csv` / `_missing_tickers.csv` | Members with a price at each month-end, to the last month with a forward return (the window's final month-end can form no portfolio and is not a row); the gap as a share of universe-months; which names lose the most months |
| `cik_map.csv` | Every (ticker, CIK) era and how it was found: the SEC's company_tickers.json, the constituents table, a hand-written override, an exact or prefix name match to its own filings, or unmatched; `start`/`end` bound an override's era |
| `cik_overrides.csv` | **Hand-written** (FIX_PLAN F1b). One row per (ticker, CIK) the audit established, with the EDGAR filing list as `source_url`, optional `start`/`end` month-ends when a ticker changed registrant (Disney 2019, CB 2016, JCI 2016), and a note giving the SEC name and the event. `sectors.cik_at` applies them; see `decisions/cik_audit.md` |
| `cik_audit_2015.csv` / `cik_audit_summary.csv` | FIX_PLAN F1: every member with no total assets at 2011-12, 2015-12 and 2022-12, the CIK the map gave it, the filer a name search over the full index finds, and a class (`map_wrong`, `foreign_filer`, `no_xbrl`, `other`); the summary counts each class per month. Written by `scripts/audit_cik_map.py` |
| `tag_gap_<concept>_<fy>.csv` | FIX_PLAN F3: for cogs and revenue in FY2011, FY2015 and FY2020, the universe filers with no value for the concept and the 20 most used tags among them whose name contains Cost, Revenue or Sales. Written by `scripts/tag_gap.py` |
| `revenue_derived.csv` | FIX_PLAN F3: per December, members whose revenue comes from a tag, is derived for a bank (net interest income + noninterest income, Financials only), or is missing |
| `tag_coverage.csv` | Per concept and fiscal year: share of universe CIKs with a 10-K value and the tag that supplied it |
| `fundamentals_coverage.csv` | Per month: members with each concept available as-of, and with a market cap |
| `market_cap_dropped.csv` | Names whose price x shares still comes out under $1bn after the split factor and the cover-page count (FIX_PLAN F2). Listed, no longer excluded: the old floor was catching split-adjusted prices meeting unadjusted counts (Chipotle's 50-for-1), not units errors |
| `shares_crosscheck.csv` | FIX_PLAN F2: every current member's SEC share count (in the price basis) against yfinance's current count and market cap; `flag` when the ratio is outside [0.5, 2]. Written by `scripts/crosscheck_shares.py` |
| `shares_overrides.csv` | **Hand-written** (FIX_PLAN F2). Tickers pinned to one share-count source (`cover`, `balance_sheet`, `weighted_average`) or marked `unresolved` and dropped from market cap, with the reason from the cross-check |
| `public_float.csv` | FIX_PLAN_3 H1: every (ticker, fiscal year) with a 10-K `EntityPublicFloat` (SEC companyconcept API, `shares.fetch_float`): the pipeline's own cap at the last month-end on or before the float date (`close` x `shares`, the count the portfolios use, in the price basis) against the float, `ratio = cap / float`, `flag` = `low` under `config.toml [checks] float_ratio_lo` or `high` over `float_ratio_hi`, and `reason` (near a split factor, near 1000, over 100x, other). A missing float or a missing cap is a null ratio and never a flag |
| `public_float_overrides.csv` | **Hand-written** (FIX_PLAN_4 J1). A float read from the 10-K cover text where the XBRL `EntityPublicFloat` is wrong, keyed on (ticker, fy), with the filing URL and the XBRL value it replaces. Exelon FY2010-2013 (XBRL $59.09bn four years running; text $25-32bn; the pipeline's cap is within 0.1% of the text). `public_float_check` applies it before the ratio and marks the row `float_source = override` |
| `public_float_summary.csv` | Per fiscal year: member-years, how many have a float and a ratio, flags and reasons. The 90%-coverage bar reads `pct_covered` |
| `yf_identity.csv` | FIX_PLAN_3 H2: one row per removed name: what yfinance says the symbol is now (`yf_name`, `exchange`, `currency`, `quote_type`, from `data/raw/yf_info_<date>.json`), the name overlap with Wikipedia's and EDGAR's names, the first price against the membership, the price `level` (close x cover count in the price basis over `EntityPublicFloat`, median over the membership) and `flag` / `reason` (`prices.identity_check`). Yahoo's delisted placeholder (`YHD` / `MUTUALFUND`, a number for a name) is recorded, not evidence; a flagged name is excluded for its whole membership |
| `price_identity_exclusions.csv` | FIX_PLAN_3 H1/H2: the ticker-months no signal or portfolio may use (`identity.py`). A `public_float` row runs from a flagged float date to the earlier of 12 months and the first later filing whose count puts the ratio back in band (`window_end`); an `identity` row is a flagged name's whole membership interval. Regenerated by `build --step fundamentals` from the two check files; `run.py` applies it before signals |
| `sec_amendments_by_year.csv` | 10-K/A and 10-Q/A as a share of filings: the size of the first-filed choice |
| `delisting_terminal.csv` | The removed names whose last print is within 45 days of removal: the only ones the `terminal` delisting sensitivity touches, with the delisting date and class (`acquired` / `failed` / `unknown`) from `delistings.csv` (FIX_PLAN F6) |
| `delistings.csv` | FIX_PLAN F6: Alpha Vantage's delisted-symbol list filtered to the universe (ticker, name, exchange, delisting_date). Absent until `ALPHAVANTAGE_API_KEY` is set and `fetch --step prices` runs |
| `price_conflicts.csv` | FIX_PLAN F6: months where yfinance's and Tiingo's returns differ by more than `config.toml [prices] conflict_threshold`; Tiingo wins those months. Empty until `TIINGO_API_KEY` is set |
| `text_coverage.csv` | Per filing year: universe 10-Ks in the FSDS index, primary documents fetched from EDGAR, documents over `min_words`, and pairs with a prior 10-K; median words |
| `text_short_documents.csv` | 10-Ks under `min_words`: wrappers whose annual report is an exhibit. Treated as missing, not parsed further |
| `text_fetch_missing.csv` | Filings in the index the submissions API did not list a primary document for, or that EDGAR refused |
| `sector_map_check.csv` / `_disagreements.csv` | SIC-to-sector agreement with Wikipedia's GICS on current members (84.5%), and every disagreement |
| `rmw_trough_disagreements.csv` / `rmw_trough_blocks.csv` | FIX_PLAN_2 G5: per name over 2013-2015, the rank gap between the RMW replica's sort and a naive net income + interest + tax sort, with what drives it; and the replica's correlation with big-cap RMW by 3-year block as reported, without Financials, with two-year equity, and without the three reused symbols (HAR, EP, COL). Written by `scripts/rmw_trough.py`; see `decisions/g5_rmw_trough.md` |
| `membership_spotcheck.csv` | **Hand-written.** 20 rows verified against S&P press releases or contemporaneous news: ordinary additions and removals across the window, every override, and every rejected `date_added` |

## Conventions the numbers depend on

- A change dated *d* means the added name is in the cross-section from *d*
  and the removed name's last day is *d − 1*. S&P announces "after the
  close of *D*"; Wikipedia usually records *D + 1*, occasionally *D*. The
  difference only reaches a month-end cross-section when *D* is the last
  trading day of a month (NRG, 2010-01-29).
- Current members carry their **current** ticker back through history;
  removed names carry the ticker they were removed under. yfinance keys
  history the same way, which is why.
- `1900-01-01` as a start means "before the record begins".
